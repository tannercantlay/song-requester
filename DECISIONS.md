# Decisions & Deviations

Log any point where the implementation deviates from `BUILD_PLAN.md` / `design.md`, with a one-line reason.

- **2026-07-03** — `setlist-poc/` (the vanilla-JS reference implementation) was never provided in this repo; only `BUILD_PLAN.md`, `design.md`, and `db/` came through. Phases are implemented directly from `design.md` §5-7 and `BUILD_PLAN.md` §3 instead of by porting POC behavior.
- **2026-07-03** — Node 20 LTS isn't installed locally (system has Node 25.8.2); proceeding with Node 25 since the codebase doesn't rely on anything LTS-specific. `engines.node` in root `package.json` is left at `>=20`.
- **2026-07-03** — `create-vite` scaffolds React 19 / Vite 8 / oxlint by default now; pinned `packages/web` back to React 18 + Vite 5 per the locked decision table, and deferred full ESLint+Prettier setup (not required by any Phase 0 "Done when" check) — revisit before Phase 4.
- **2026-07-03** — Local `docker-compose` Postgres has no TLS cert configured, so `dbmate`/`pg`'s default `sslmode=require` fails with "SSL is not enabled on the server". Added `?sslmode=disable` to `DATABASE_URL` in `.env`/`.env.example` for local dev only (DB is `localhost`-only, not network-exposed). A real deployment (RDS/managed Postgres, `design.md` §12) must use `sslmode=require` or drop the param — don't copy this into prod config.
- **2026-07-03 (Phase 3)** — Removed `DEV_AUTH_BYPASS` from `env.ts`/`.env`/`.env.example` per the Phase 3 goal ("remove the Phase 1 dev-auth flag"); `requireAdmin` now does real JWT verification.
- **2026-07-03 (Phase 3)** — No live Spotify Developer credentials were available in this environment (`SPOTIFY_CLIENT_ID`/`SECRET` are blank). The OAuth connect/callback/import routes are fully implemented and unit-verifiable, but the actual OAuth handshake (redirect to Spotify, user consent, token exchange) requires real credentials and a browser — untested end-to-end here. Fill in the Spotify env vars and click through `/admin/catalog` → Connect Spotify to complete Phase 3's "Done when" check.
- **2026-07-03 (Phase 3)** — Rate limit on `POST /api/e/:token/requests` set to 1 request per 3 seconds per `(IP, requesterToken)` pair — design.md §11 only specifies "~1 request / few seconds" as an example, not an exact number.
- **2026-07-03 (Phase 3)** — `@fastify/jwt`/`@fastify/cookie`/`@fastify/rate-limit`/`@fastify/csrf-protection` were all pinned to their latest majors during Phase 0 scaffolding, but those majors target Fastify 5; our locked stack is Fastify 4 (BUILD_PLAN §0). Downgraded `@fastify/rate-limit` to `^7.6.0` and `@fastify/csrf-protection` to `^6.4.1` (both Fastify-4-compatible per their READMEs) — startup was throwing `FST_ERR_PLUGIN_VERSION_MISMATCH` before this fix. Also `@fastify/rate-limit@7`'s `.d.ts` doesn't resolve cleanly under our `moduleResolution: NodeNext` (default import types as the whole module namespace instead of the plugin function); worked around with a scoped cast in `server.ts` rather than fighting the type resolution — the runtime export is a plain Fastify plugin function, so the cast is safe.
- **2026-07-04 (Phase 3)** — User-requested scope addition beyond `design.md`'s "single admin, no multi-tenancy" (§1): added `POST/GET/DELETE /api/admins` (admin management CRUD) and a `/admin/team` UI so a co-host can get their own login for live events. Every admin shares the same events/catalog/queue (no roles/permissions) — this is "multiple people, one shared account space," not real multi-tenancy. Guards: can't delete your own account or the last remaining admin.
- **2026-07-04 (Phase 3)** — User-requested addition: `PATCH /api/events/:id` now also accepts `name` (event rename), with a click-to-edit control in the admin header. Not in `design.md` §6's original endpoint body, but a natural extension of the same endpoint.
- **2026-07-05 (Phase 3)** — User-requested addition: since Amazon Music has no public API for reading playlists (only the Alexa Skills API, which doesn't cover this), added `POST /api/songs/import` accepting a CSV/Excel (`.csv`/`.xlsx`/`.xls`) file upload as an alternative catalog import path, alongside Spotify. Dedupes against the existing catalog by case-insensitive `(title, artist)` match (skips rather than erroring); rows missing a title or artist are reported back per-row instead of failing the whole upload. Added `@fastify/multipart` (pinned to `^8.3.1`, the Fastify-4-compatible major, matching the pattern already hit with rate-limit/csrf-protection) and `xlsx` (SheetJS) for parsing.
- **2026-07-05** — User-requested addition: free-text `genre` column on `song` (migration `0002`), not in `design.md`'s original data model (§5). Wired through catalog CRUD, CSV/Excel import (`Genre`/`Category`/`Style` header aliases), and the guest-facing song list (`GET /api/e/:token/songs` now also returns a distinct `genres` list and accepts `?genre=` to filter). Kept as free text with an autocomplete `<datalist>` in the admin UI rather than a fixed enum, since real-world genre tagging is inconsistent and personal-catalog use doesn't need strict taxonomy. Spotify-imported tracks still get `genre: null` — the Spotify Web API only exposes genre at the artist level (an extra API call per unique artist), so it's left editable after import rather than auto-populated.
